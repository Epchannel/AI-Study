# Học Cùng

Vietnamese learning chatbot built on OpenTutor. Open `/` for the new academy; `/workspace` preserves the previous course workspace.

## Accounts and classroom workflow

1. Register the first account to initialize the teacher. Later registrations are student accounts. There is no shared default password.
2. Teacher: **Góc giảng viên → Tạo lớp**. Share the displayed join code with students.
3. Student: **Hồ sơ học tập → Lớp học & học liệu**, enter that code.
4. Teacher: upload PDF/DOCX/PPTX/TXT/Markdown, up to 25 MB per file. Review extracted text, classification and formulas, then publish. Scanned PDFs must be OCRed before upload.
5. Choose a class in the chat source selector, then select **Tất cả tài liệu của lớp** or an individual document. The choice is saved with the conversation and restored from history. Source changes start a new conversation. Students' answers use published material only; an archived or withdrawn selected document stops further generation and asks for a new source. Downloadable references show retrieved sources; individual `[n]` citations are generated by the model and should be checked against those references. Chat-generated quizzes/cards inherit the selected document.
6. Generate quiz/flashcards in **Quiz & Flashcard**. Teachers selecting a class get drafts; edit and publish to assign them. Personal student exercises stay private. Requests such as “Tạo 5 câu quiz từ bài vừa học” in chat create a saved exercise with an open button.
7. Quiz answers are hidden from students until submission. Submitting updates topic statistics and the wrong-answer notebook. Flashcard reviews use the repository's FSRS scheduler and persist separate state for each student.
8. Fill in goals, exam date, subjects, available hours and career interests in **Hồ sơ học tập**. Scheduling respects available hours, existing appointments, daily budgets and exam dates, prioritizes observed weak subjects and uses matching class assignments with deadlines when possible.
9. Mark study sessions completed, submit quizzes or review due flashcards to earn daily activity. Opening chat does not increment streaks. Streaks use UTC+7 (Vietnam) and count distinct days, preserving yesterday's streak until today's end.
10. **Khám phá hướng nghiệp** uses the saved interview profile and a dedicated conversation history. Suggestions are educational guidance; current admissions/tuition facts require dated references. The chatbot cannot browse live admissions information.

In **Góc giảng viên**, search the material library by title, filename, chapter or lesson and combine publication-state and level filters. Select a class to filter by subject/grade. Each active material has **Tạo quiz / Tạo flashcard** actions: these create a draft tied to that material's saved version and open the editor for teacher review before publication. Save material edits before generating an exercise.

The career chat contains **Bản định hướng nghề nghiệp của tôi**. Complete interests, strengths and constraints in the profile first; the saved report compares alternatives, preparation and experiments. It shows its date and warns when profile data has changed. The general MOET link is a lookup resource, not evidence for a particular school's current admissions requirements.

Teachers see class assignment results and class flashcard progress, not students' personal chats or career profiles. Academic records and source files are kept in SQLite/local uploads. SQLite startup upgrades back up existing databases before adding tables.

If the gateway fails, the UI explains timeout/rate-limit/access errors and displays a request ID when available. Keep that ID when reporting the problem. Generations are not retried automatically; partial streams are not saved as successful answers. HNQ streaming requires the real `[DONE]` marker even if a preceding chunk contains a finish reason.

HNQ uses upstream streaming for long structured generations too; the backend collects the stream and returns a complete result only after the terminal event. Rescheduling stores times in UTC+7 and recalculates duration; a session must stay within one day and last 1–240 whole minutes. Skipped sessions can be restored only if the slot is free. Completed sessions cannot be edited, and repeated completion does not earn extra streak activity. Manual rescheduling can use a new time outside the saved availability; automatic generation uses availability and the chosen daily budget.

## Run locally

Backend, from `apps/api`:

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-core.txt
.venv/Scripts/python.exe -X utf8 -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Frontend, from `apps/web`:

```powershell
npm ci
npm run dev -- --hostname 127.0.0.1
```

Keep `JWT_SECRET_KEY` persistent in the backend's private `.env`, along with the HNQ configuration described in [hnq-gateway.md](hnq-gateway.md). Rotating it signs everyone out. The current local development servers bind to loopback.

Academy endpoints always validate a bearer token independently of legacy local workspace mode. Before any shared network deployment enable the existing authenticated deployment mode; do not expose unauthenticated legacy routes. CSRF headers are included by the academy frontend when middleware is active. Teacher bootstrap should be completed locally by the installation owner before deployment.

## Verification

```powershell
# At repository root, in an environment containing runtime + pytest + pytest-asyncio:
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
apps/api/.venv/Scripts/python.exe -m pytest -p pytest_asyncio.plugin -o addopts= tests/test_academy.py tests/test_career_guidance.py tests/test_hnq_gateway.py tests/test_fsrs.py -q

# From apps/web:
npx tsc --noEmit
npx eslint src/components/academy src/lib/academy-api.ts
npx vitest run src/lib/academy-api.test.ts src/components/academy

# From apps/api; uses temporary accounts/database and removes its data afterwards:
.venv/Scripts/python.exe -X utf8 ../../scripts/smoke-academy.py
# Add --live-llm for three real HNQ generations (chat, quiz, flashcards).
```

Curriculum metadata is supplied by teachers (subject, grade, chapter, lesson, level). No official textbook corpus, current admissions database, external notifications or multi-school administration is bundled. Teacher approval remains necessary for generated class materials and assessments.
